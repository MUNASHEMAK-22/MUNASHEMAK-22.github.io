What the data model looks like

A single fact table (sales) with one row per order line, related to dimension attributes for region, product, and date. The three headline measures are defined once and reused across every visual:

Total Revenue = SUM(sales[revenue])
Total Profit  = SUM(sales[profit])

Profit Margin % =
    DIVIDE([Total Profit], [Total Revenue], 0)

YoY Growth % =
    VAR CurrentYear = [Total Revenue]
    VAR PriorYear =
        CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(sales[order_date]))
    RETURN
        DIVIDE(CurrentYear - PriorYear, PriorYear, 0)

Because the measures are defined centrally rather than hardcoded per chart, every visual on this page — and every visual in the actual Power BI file — stays consistent automatically when the underlying data refreshes.

The insight

In the synthetic dataset, overall revenue grew a modest 1.4% year-over-year — but that headline number hides a real pattern. North grew 10.7% and East grew 7.7%, while West declined 12.2%, concentrated almost entirely in Q3. Without the regional breakdown, the West decline is invisible behind a healthy-looking company-wide average.

This is the same underlying dataset pattern used in the ETL Pipeline project, viewed through a different lens: there, the story was about data quality; here, it's about what a single blended KPI can hide until you slice it.
